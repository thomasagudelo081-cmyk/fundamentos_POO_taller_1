# fundamentos_POO_taller_1
Respuestas a Preguntas de Comprensión - Taller 2
1. ¿Qué ventaja tiene dibujar el diagrama UML antes de escribir el código? Te ahorra tiempo y dolores de cabeza. Primero maquetas la estructura de la clase y ves rápido si te faltan atributos o métodos. Es básicamente hacer el plano de la casa antes de tirarse a pegar ladrillos en el código.
2. ¿A qué parte del código corresponde cada una de las tres divisiones del diagrama de clases?
Arriba: El nombre de la clase (public class NombreClase).
En el medio: Los atributos (las variables globales o de instancia con su tipo de dato).
Abajo: Los métodos (las funciones con sus parámetros y si retornan o no algo).
3. ¿Cuál es la diferencia entre un comentario // y un bloque /** ... */ de Javadoc? El // es una nota rápida para ti o tus compañeros para entender una línea puntual del código. El /** ... */ de Javadoc es documentación oficial que luego NetBeans puede compilar en una página HTML para que cualquiera pueda usar tu clase como una librería sin tener que leer tu código por dentro.
4. ¿Por qué es importante documentar el código en un equipo de trabajo? Porque nadie lee mentes y en proyectos reales nadie trabaja solo. Si no documentas, el que vaya a usar o arreglar tu código después tiene que perder horas adivinando qué hace cada variable o método. Se evita perder tiempo y romper cosas en producción.
